## Cobertura de segurança

Os testes verificam claims ausentes/incorretos, expiração, adulteração, tipo errado, HS256 recusado, chave antiga aceita durante sobreposição e recusada após retirada, verificação sem privada, configurações obrigatórias, ausência de SQLite em produção, chaves PII/HMAC independentes, leitura durante rotação Fernet, senha multibyte, refresh não rastreado, replay, logout idempotente, usuário desativado e preservação do bootstrap.

Os testes HTTP de contrato existentes usam TestClient e SQLite. Não equivalem ao fluxo HTTP passando pelo Kong real. O banco PostgreSQL foi usado nas migrações e no bootstrap, mas o teste concorrente de renovação não chegou a executar.

## Validações pendentes para encerrar o aceite

1. Com a stack já iniciada, executar:
   `uv run --frozen python scripts/smoke_s1.py`.
   O script testa health/Swagger dos sete serviços, autenticação através do Kong, tipo de token, rotação/logout e duas renovações simultâneas no PostgreSQL. A tentativa foi recusada pela autorização de execução; não foi repetida por outro meio.
2. Conferir em execução o UID 10001, ausência de ferramentas dev e isolamento da privada em auth. A configuração e o build foram revisados; os comandos de inspeção previstos não chegaram a executar após a recusa.
3. Executar a CI no repositório remoto após revisão/publicação. O workflow foi criado, mas não foi acionado remotamente.
4. Para prova estrita de checkout limpo, reproduzir o README em checkout dos arquivos após seu versionamento. O build local foi feito com contexto por allowlist, sem .venv, .env ou secrets do host.
